# Qwen3.6 language-tool qualification, September 20, 2026

Clearer descriptions resolved opaque-handle confusion in the measured cases.
Actual agent workflows still made position-selection errors, then recovered
using references. Schema validity, first-call correctness, required-fact
coverage, and manual answer review are reported separately.

This report records the original position-based interface. The subsequent
[reliability follow-up](2026-09-20-lsp-reliability.md) changes source targeting
and records additional failures and fixes; the original measurements below are
retained. The description A/B probe now runs against the current schema, so
rerunning it does not exactly reproduce this historical interface.

The user-supplied Tailnet deployment advertised model `qwen3.6`, backed by
`unsloth/Qwen3.6-35B-A3B-NVFP4-Fast`, through vLLM. Only synthetic fixture code
was sent. The serving configuration was not changed.

## Controlled selection checks

The initial eight-case probe passed **6/8**. `lsp_navigate` and `lsp_references`
failed because the model called `lsp_symbols` with `query="loc_example_1"`.
Those cases supplied a handle in a user message without a preceding tool receipt.

A 24-call comparison varied description wording and conversational context.
Each cell contains three definition requests and three reference requests.
Within each pair, schemas, user request, system instructions and generation
settings stayed fixed; variant order alternated. The preceding receipt, when
present, was a controlled synthetic outline result.

| Handle context | Original descriptions | Clarified descriptions |
| --- | ---: | ---: |
| User-supplied handle only | 0/6 correct | 6/6 correct |
| Prior outline tool receipt | 6/6 correct | 6/6 correct |

Correct means the requested tool, valid arguments, unchanged `ref`,
`target_kind="reference"`, and the requested relation/declaration option.
Every emitted call was structurally valid, including calls to the wrong tool.
This was a semantic selection problem, not a JSON/schema rejection.

Clarifications now shipped in the tool descriptions explain that `loc_` values
are opaque handles, must be copied into `ref`, and must not be searched as symbol
names. They explain direct reference targeting for inspect/navigation/references.
No tool names, schemas, or runtime dispatch semantics changed.

The complete eight-case probe then passed **24/24** over three runs, covering all
seven tools and both inspect target forms. Requested argument values were also
checked in the saved calls. Sampling was temperature 0, maximum 1,024 output
tokens, and server-default thinking. Median call latency was **3.408 seconds**;
aggregate usage was **71,601 input / 4,241 output tokens**. These repetitions are
a small smoke test, not independent evidence of broad model reliability.

## Real harness and gopls

The fixture contains `pricing.RateFor`, two callers in other packages, an
unrelated same-name function, and a separate package with a return-type error.
The task asks for the exact callers, implementation, prices, and diagnostics.
Normal root instructions and the full local/workflow tool roster are available;
there is no prescribed tool sequence. Web tools and automatic token-count
requests are disabled. Fixture files must remain unchanged.

These trials use the bundled `qwen3.6` profile: thinking enabled, temperature 1,
top-p 0.95, top-k 20, repetition penalty 1.1. Evaluation caps output at 8,192 tokens
per model call, each trial at four minutes, and generation at 24 calls.

| Trial | Required facts present | LSP calls | Schema-invalid | Rejected execution | Returned refs reused | Model calls | Duration |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Original descriptions/prompt | Yes | 5 | 0 | 1 | 1 | 6 | 64.9 s |
| Clarified descriptions/prompt, 1 | Yes | 5 | 0 | 1 | 2 | 5 | 38.8 s |
| Clarified descriptions/prompt, 2 | Yes | 7 | 0 | 2 | 1 | 9 | 69.1 s |

The original trial targeted column 1 (`func`) rather than the identifier.
The first clarified trial provided mismatching `expected_text` for a navigation
position. The second guessed incorrect columns twice for inspection. Guards
rejected these requests; all three workflows recovered using actual returned
handles, identified the correct callers, excluded the unrelated function, and
reported the compiler diagnostic. No invented handles or fixture edits occurred.

Manual review found extra inaccuracies in the clarified answers. Trial 1 said
the five files were in four packages; the fixture has five packages. Trial 2
said the unrelated `legacy.RateFor` was never referenced, although `legacy.Quote`
calls it in the provided source. Thus the required-fact checks passing does not
mean either entire answer is correct. Saved metrics from this run called that
narrow check `task_success`; the evaluator now calls it `required_facts_present`
to avoid that misleading interpretation. The original artifacts are preserved.

The harness instruction was strengthened to prefer returned references and put
explicit positions inside identifiers. The clarified trials show this instruction
does **not** eliminate guessing. Their strict zero-rejection test still fails.
Tool coverage also varies: the final trial did not call navigation. Recovering
the requested facts does not validate every operation. The first trial's initial evaluator
also failed on missing inspect/navigation and fewer than two handle reuses; later
evaluation records optional tool coverage separately from task correctness.

The remaining interface issue is reliable position selection before the model
has a handle. Further work should evaluate stronger discovery-first guidance or
identifier-based addressing against manually calculated columns. These runs do
not establish other languages' model-driven task success, stale-handle recovery,
pagination, editing success, or comparative performance against text-search-only
agents. The feature remains experimental.

## Reproduction and artifacts

Set `STRAP_LIVE_BASE_URL` to the deployment root and `STRAP_LIVE_MODEL=qwen3.6`.
Install `gopls` for the harness trial. The comparison includes a deliberately
retained original-description control and can exit nonzero for those failures.
Harness trials also exit nonzero if any tool request is rejected, even if the
task answer is correct.

```sh
STRAP_LIVE_LSP=1 go test ./tool -run '^TestLiveLanguageSchemas$' -count=3 -v
STRAP_LIVE_LSP_AB=1 go test ./tool -run '^TestLiveLanguageDescriptions$' -count=1 -v
STRAP_LIVE_LSP=1 STRAP_LIVE_PROFILE=qwen3.6 STRAP_LIVE_LSP_TRIALS=2 \
  go test ./harness -run '^TestLiveLanguageTraversal$' -count=1 -timeout 10m -v
```

`STRAP_LIVE_LSP_OUTPUT` selects a persistent directory for comparison metrics and
harness traces. This run's local artifacts are under the git-ignored
`eval/results/2026-09-20-lsp-qwen36/`: schema test logs and normalized measurements,
the 24-call description comparison, and three full harness traces with metrics,
tool arguments/results, token totals, and final answers. Both original failures
and successful checks are retained. Ordinary offline tests skip all live calls.

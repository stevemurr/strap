# qwen3.8-flash-next: thinking vs no-thinking, and what the harness got wrong

Runs on the 60-task ladder with the harness at commit `1fd9a4c` plus the
uncommitted qwen3.8 presets in the working tree.

| run | preset | results dir | tasks | passed |
|---|---|---|---|---|
| thinking | `qwen3.8-flash-next-thinking`: max_tokens 1500, reasoning_effort low, temperature 1.0, top_p 0.95 | `eval/results/2026-09-16-qwen3.8-thinking-vs-nothink/1fd9a4c-dirty_qwen3.8-flash-next-thinking_20260915-214838` | 60 | 26 (43%) |
| no-thinking | `qwen3.8-flash-next-nothink`: max_tokens 600, thinking off, temperature 0.7, top_p 0.8 | `eval/results/2026-09-16-qwen3.8-thinking-vs-nothink/1fd9a4c-dirty_qwen3.8-flash-next-nothink_20260916-095025` | 29 (stopped early) | 6 (21%) |

For scale, the same harness build ran qwen3.6 without thinking on the full
ladder the same afternoon (`eval/results/2026-09-16-qwen3.8-thinking-vs-nothink/1fd9a4c_qwen3.6-nothink_20260915-162609`) and passed 59 of
60, up from 56 before the seven harness fixes; `create_plan` without a title
was accepted 20 times, no-op plan edits were rejected 6 times, and a root's
`wait_for_input` was rejected once.

## The two variants on the 29 tasks both attempted

| | thinking | no-thinking |
|---|---|---|
| passed | 19 | 6 |
| passed by both | 5 | 5 |
| passed by one only | 14 | 1 (easy-20) |
| mean task time | 7.5 min | 2.4 min |
| truncated tool calls ("arguments are incomplete JSON") | 70 in 60 tasks | 127 in 29 tasks |
| bare "finish reason length" failures | 49 | 1 |
| tasks where an agent died of "history output mismatch" | 38 of 60 | 25 of 29 |
| root died of it | 33 | most |

No-thinking tasks mostly end in about a minute after 6 to 9 calls: the root's
`assign_work` call, whose task and context text runs to 2,000 to 2,400 bytes,
is cut off at the 600-token cap, the retry corrupts the projection (below),
the root's next workflow call fails, and the root exits with a failure. The
thinking variant survives that step because 1,500 tokens fit an assignment,
then loses implementors the same way on `write_file`.

## Cause 1: the output caps are far below what one tool call needs

Measured on the truncated calls:

| | thinking (cap 1500) | no-thinking (cap 600) |
|---|---|---|
| arguments at cut-off, mean | 1,727 bytes | 1,386 bytes |
| reasoning before the call, mean | 1,630 bytes | 0 |
| total output at cut-off, median | 4,319 bytes (about 1,200 tokens) | 1,660 bytes (about 460 tokens) |
| bare length failures, median output | 5,724 bytes (about 1,590 tokens) | |

A solution file for these tasks is 1,300 to 4,600 bytes of JSON-escaped
argument text. At 600 tokens no `write_file` of a real solution can complete;
at 1,500 tokens it completes only when the model reasons briefly first, and
"low" reasoning effort still spent 5 to 7 KB on many calls. Researchers and
auditors hit it on long `report_work_progress`, `submit_research` and `shell`
arguments. This is configuration, not model quality: the same model with a
32K cap would not show most of these failures.

## Cause 2: a harness bug turns every truncated call into a dead agent

When the provider rejects a tool call whose arguments never closed, the agent
discards the call and appends a user-role notice asking for it again. That
notice is recorded with a pointer to the failed output
(`appendHistory(..., &output)` in `agent/agent.go`). The projector's replay
invariant requires a history record that names an output to be an assistant
message on an output that is still active; the output has already finished
as failed, so replay stops with "history output mismatch". From then on every
projection read in that session fails: `report_work_progress` (the largest
single error source in the thinking run, 39 of 73), `get_work`, `ListWork`,
the wait guard. The agent that made the read exits with "project record N:
history output mismatch", usually the root.

The reasoning-limit retry added on 2026-09-15 records its notice the same way,
so it has the same bug; qwen3.6 rarely triggered either path, which is why
the earlier runs did not show it (2 tasks in the qwen3.6 thinking rerun did).

Seventeen thinking tasks still passed because the implementor had written the
file before the root died.

## Cause 3: the retry cannot succeed and is not bounded

The notice says "emit the call again with every parameter closed", which is
right for a syntax slip and wrong for a cap: the model re-emits the same
oversized call. The two-retry limit resets after any successful call, so an
implementor alternating a small successful call with a truncated `write_file`
runs until the budget (easy-05 no-thinking: 126 calls, 30 truncated writes,
timed out). The provider already knows the finish reason; the notice does not
use it.

## Smaller patterns

- **Research for reading the README.** qwen3.8 assigned 20 research tasks in
  19 of 60 thinking tasks, nearly all "Read README.md and extract the
  contract". qwen3.6 never did. The root prompt's "assign investigation
  phases to researchers" invites it; researchers then fail on long progress
  reports and the root waits.
- **Workers outlive a dead root.** After a root exits, implementors and
  auditors keep running and fail on `send_message` with "agent stopped:
  agent-1" (11 times). Nothing cancels the session's other agents when the
  root is gone.
- **Progress-report schema.** Beyond the projection failures, models put
  `objective` at the top level instead of `position.objective` (8), send
  `null` for optional fields (2), and add `uri` inside a finding (3).
- **Server outage.** hard-03, hard-04 and hard-05 failed at 07:28 with
  "dial tcp" on the first call. The runner graded them as `failed`; they
  are infrastructure and should be `error`.

## Harness-side fixes, in order of payoff

1. **Record retry notices without the output pointer** (`agent/agent.go`,
   both the malformed-call and reasoning-limit paths), and add a test that
   replays the projection after a rejected call. This alone removes the
   death of 33 roots in the thinking run.
2. **Make the truncation retry honest and bounded.** When `FinishReason` is
   `length`, the notice should say the output limit cut the call off after N
   bytes and ask for less accompanying text or a smaller call; count
   truncations per exchange without resetting on success and stop after a
   handful.
3. **Let a small output budget write a file in pieces**: an `append` mode on
   `write_file`, or documenting `edit_file` for incremental construction, so a
   model that cannot emit 2 KB in one call can still finish.
4. **Stop the session's workers when the root exits with an error.** A dead
   root cannot receive their results; letting them run only burns budget and
   produces "agent stopped" noise.
5. **Prompt: no research for workspace files.** Researchers are for external
   sources and questions the workspace cannot answer; implementors read the
   README themselves.
6. **Accept the common progress-report mistakes**: alias a top-level
   `objective` into `position`, treat `null` as absent.
7. **Runner: classify a session whose model calls never succeeded because of
   a connection error as `error`, not `failed`.**

With 1 and 2 in place, rerun the thinking variant unchanged to measure the
harness effect, then raise the caps (8K to 16K for thinking, 4K for
no-thinking) to measure the model.
